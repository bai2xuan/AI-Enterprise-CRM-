| 项 | 内容 |
|---|---|
| 系统名称 | AI Enterprise CRM |
| 底座 | SuiteCRM 7.15.2（AGPL-3.0） |
| 运行时 | PHP 8.3.35 (NTS) |
| 数据库 | MariaDB 10.11.19（utf8mb4） |
| 设计原则 | **不修改核心源码**，全部定制走官方扩展机制 |

---

## 一、设计目标与约束

### 1.1 目标

1. **可运行**：本地一条命令起服务，登录即可完整演示 5 大模块；
2. **可交付**：提供 Docker 部署方案与本地便携部署方案（双轨）；
3. **可升级**：SuiteCRM 升级时定制内容不丢失；
4. **可验证**：每一项定制都能被脚本自动化验收。

### 1.2 硬约束

| 约束 | 说明 |
|---|---|
| 核心代码零改动 | 所有定制必须落在 `crm/custom/` 或**新增模块目录**（新模块本身不是核心代码） |
| 不破坏原生统计 | 销售阶段、概率等被硬编码的 Key 一律保留英文 |
| 离线可用 | 不依赖任何外网 CDN 或第三方 API |

## 三、扩展机制设计

### 3.1 四层改造策略

```
┌──────────────────────────────────────────────────────────────────┐
│ 配置层   Studio / 管理后台   →  下拉项、页面布局、权限矩阵        │  零代码
├──────────────────────────────────────────────────────────────────┤
│ 扩展层   custom/Extension/  →  Vardefs 加字段、Layoutdefs 加子面板│  官方机制
│          + 语言包扩展            Language 中文化、LogicHooks 自动化│
├──────────────────────────────────────────────────────────────────┤
│ 增强层   新增模块 + 自定义视图 →  需求调研、项目交接、销售分析看板 │  独立模块
├──────────────────────────────────────────────────────────────────┤
│ 核心层   SuiteCRM 原生代码   →  【不修改，一行不改】               │
└──────────────────────────────────────────────────────────────────┘
```

### 3.2 扩展文件的加载链路

SuiteCRM 的扩展是「**声明式源码 → 合并产物 → 运行时加载**」三段式：

```
【源码】crm/custom/Extension/modules/<Mod>/Ext/Vardefs/xxx.php
            │  Quick Repair and Rebuild (rebuildExtensions)
            ▼
【产物】crm/custom/modules/<Mod>/Ext/Vardefs/vardefs.ext.php
            │  entryPoint 启动时 include
            ▼
【运行时】$dictionary / $beanList / moduleList / logichooks 生效
```

关键点：
- `custom/Extension/**` 是**源码**（必须入库）；
- `custom/application/**` 与 `custom/modules/*/Ext/**` 是**产物**（不入库，由 repair 重建）。

### 3.3 自定义模块的文件规范

新增一个 SuiteCRM 模块，最少需要 6 类文件：

| 文件 | 作用 |
|---|---|
| `modules/<Mod>/<Mod>.php` | Bean 类（继承 SugarBean） |
| `modules/<Mod>/<Mod>_sugar.php` | Bean 基类（字段/关系声明） |
| `modules/<Mod>/vardefs.php` | 表结构与字段定义 |
| `modules/<Mod>/metadata/detailviewdefs.php` | 详情页布局 |
| `modules/<Mod>/metadata/editviewdefs.php` | 编辑页布局 |
| `modules/<Mod>/metadata/{listviewdefs, searchdefs, SearchFields, subpaneldefs}.php` | 列表 / 搜索 / 子面板 |
| `modules/<Mod>/language/{zh_CN, en_us}.lang.php` | 语言包 |
| `modules/<Mod>/Menu.php` | 模块内左侧菜单 |

外加两处**运行时注册**（否则模块能访问但不出现在导航和权限页）：

| 注册项 | 存储位置 | 注册方式 |
|---|---|---|
| ACL 动作 | `acl_actions` 表 | `ACLAction::addActions($module, 'module')` |
| 顶部导航 | `config` 表 `MySettings.tab`（base64+serialize） | `Administration::saveSetting('MySettings','tab', ...)` |

> 踩坑记录：导航**不是**读 `include/tabConfig.php`，而是读 Administration 设置的序列化模块清单，
> 因此改 `tabConfig.php` 不会让新模块出现在顶部导航。

## 五、关键实现

### 5.1 客户字段扩展 + 页面布局覆盖

- **字段**：`crm/custom/Extension/modules/Accounts/Ext/Vardefs/ai_accounts_fields.php`
- **布局**：`crm/custom/modules/Accounts/metadata/{detailview,editview}defs.php`

**为什么用覆盖而不是扩展合并**：SuiteCRM 的 `custom/modules/<Mod>/metadata/*defs.php` 是
**完整替换**（不是合并），且文件内含 `EmailAddress::getSendConfirmOptInEmailActionLinkDefs()`
这类运行时调用，无法用 `include + var_export` 生成 →
本项目采用「从核心文件复制 + 精确文本片段插入新 panel」的方式生成，脚本见 `scripts/dev/gen-viewdefs.php`。

**面板分页签的关键约束**：`templateMeta.tabDefs` 中每个面板必须 `newTab => true`。
若全部为 `false`，`.tab-content` 会渲染为空、所有面板被置为 `display:none`，
页面表现为「只有标题、内容区一片空白」。

### 5.2 销售阶段中文化（不破坏统计）

`Closed Won` / `Closed Lost` 被硬编码在以下位置：

| 位置 | 用途 |
|---|---|
| `include/SugarObjects/templates/sale/metadata/SearchFields.php` | 销售模板搜索条件 |
| `modules/Opportunities/ListViewTop.php` | 首页 Top 商机 |
| `modules/Opportunities/Opportunity.php` | Bean 业务逻辑 |
| `modules/Opportunities/Dashlets/MyOpportunitiesDashlet/MyOpportunitiesDashlet.data.php` | Dashlet 数据源（硬编码完整阶段列表） |

**结论**：阶段 **Key 必须保留英文**，只通过语言包覆盖显示标签：

```php
// crm/custom/Extension/application/Ext/Language/zh_CN.ai_sales_stage.php
$app_list_strings['sales_stage_dom']['Prospecting']        = '初步接触';
$app_list_strings['sales_stage_dom']['Needs Analysis']     = '需求调研';
$app_list_strings['sales_stage_dom']['Value Proposition']  = '方案设计';
$app_list_strings['sales_stage_dom']['Perception Analysis']= '产品演示';
$app_list_strings['sales_list']['Negotiation/Review']      = '商务谈判';
$app_list_strings['sales_stage_dom']['Closed Won']         = '成交';
$app_list_strings['sales_stage_dom']['Closed Lost']        = '输单';
```

### 5.3 自定义模块脚手架生成器

`scripts/dev/build-modules.php` 用**数据驱动的声明式定义**（`$MODULES` 数组）生成 3 个模块的 46+ 个文件，
保证：
- 字段命名、类型、语言标签三者一致；
- 三个模块的布局风格统一；
- 需要新增模块时只加一段数组定义。

内置的关键处理：

| 函数 | 解决的问题 |
|---|---|
| `relate_fields()` | 自动生成 relate 三件套；外键名由 `preg_replace('/_name$/','_id',$name)` 推导 |
| `o2m()` | 生成一对多关系；link 名统一 `strtolower($module)`，避免出现 `accountss` 这类错误 |
| `expand_field()` | 自动为 currency 字段补齐 `currency_id` 与 `getCurrencyDropDown` 渲染器 |
| `tabdefs()` | 保证每个面板 `newTab => true`（见 5.1 的坑） |
| `panels_to_defs()` / `template_meta()` | 由「字段分组定义」生成 detailview / editview / quickcreate 布局 |

### 5.4 模块运行时注册

`scripts/setup/register-modules.php` 幂等地完成：

1. `ACLAction::addActions($module, 'module')` → 写入 8 个标准动作；
2. 读 `config.MySettings.tab` → base64 解码 → 追加新模块 → 写回。

### 5.5 销售分析看板

- **模块**：`AID_SalesAnalytics`（view_only）
- **视图**：`modules/AID_SalesAnalytics/views/view.list.php`
- **类名约束**：SuiteCRM 的 `ViewFactory` 按 `ucfirst($module) . 'View' . ucfirst($type)` 找类，
  且 `action=index` 会被 `action_remap` 重映射为 `listview` → 因此看板必须命名为
  `views/view.list.php` + 类 `AID_SalesAnalyticsViewList`，模块默认入口才会落到看板。
- **数据来源**：直接 SQL 聚合 `accounts` / `opportunities`，不落地中间表。
- **漏斗口径**：累计口径（进入该阶段及后续阶段的商机数），因此呈单调递减的标准漏斗形状。
- **图表库**：`custom/include/ai_assets/echarts.min.js`（本地），`echo` 方式引入，无 CDN。

### 5.6 业务自动化：成交 → 自动生成项目交接单

**注册**（源码）：`crm/custom/Extension/modules/Opportunities/Ext/LogicHooks/ai_handover_hook.php`

```php
$hook_array['after_save'][] = array(
    60, '商机成交后自动生成项目交接单',
    'custom/modules/Opportunities/ai_handover_hook.php',
    'AI_OpportunityHandoverHook', 'afterSave',
);
```

**实现**：`crm/custom/modules/Opportunities/ai_handover_hook.php`

执行流程：

```
after_save(Opportunity)
   ├─ sales_stage !== 'Closed Won'            → return
   ├─ 全局重入标记已置位                       → return（防重入）
   ├─ 按 opportunity_id 查到已有交接单         → return（幂等）
   ├─ 置位标记
   ├─ 创建 Hand_ProjectHandovers（继承客户/商机/产品/金额/货币/负责人）
   ├─ 建立 accounts / opportunities 关系
   ├─ 创建 Tasks「项目交接准备」派发给销售负责人
   └─ 清除标记
```

**设计取舍**：用逻辑钩子而非 AOW 工作流，是因为交付起点必须与销售点击保存**同时**发生，
不能依赖调度器轮询周期。验收脚本 `scripts/verify/verify-automation.php` 覆盖：
正常触发、字段继承、状态初值、待办派发、幂等性、回滚。

### 5.7 本地化

| 项 | 实现 |
|---|---|
| 默认语言 | `config_override.php` → `default_language = zh_CN` |
| 默认货币 | `default_currency_name/symbol/iso4217 = 人民币 / ¥ / CNY` |
| 日期格式 | `default_date_format = 'Y-m-d'` + **已有用户偏好批量修正**（`scripts/setup/apply-locale-preferences.php`） |
| 官方语言包残留 | 用 `zh_CN.ai_*_zhfix.php` 覆盖高频未翻译项，不改核心语言文件 |

> 为什么需要单独修正用户偏好：`config_override.php` 的 `default_date_format` 只影响**新建用户**，
> 静默安装阶段创建的 admin 已把 `m/d/Y` 写进 `user_preferences`，因此需要脚本回写偏好。

## 六、部署方案

### 6.1 方案一：Docker（推荐交付形态）

```
deploy/docker/
├── Dockerfile            # PHP 8.3 + Apache + SuiteCRM
├── docker-compose.yml    # web + db 两个服务
├── entrypoint.sh         # 首次启动执行 SuiteCRM 静默安装
├── php.ini               # 上传大小、内存、时区
├── apache-vhost.conf     # DocumentRoot 指向 /var/www/html/crm
└── .env.example          # 端口 / 数据库 / 管理员账号模板
```

### 6.2 方案二：本地便携栈（本项目实际运行/截图所用）

| 组件 | 路径 | 端口 |
|---|---|---|
| PHP 8.3.35 NTS | `tools/php/` | 8080 |
| MariaDB 10.11.19 | `tools/mariadb-10.11.19-winx64/` | 3307（避开系统 3306） |

启动：

```bash
tools/php/php.exe -S 127.0.0.1:8080 -t crm
tools/mariadb-10.11.19-winx64/bin/mysqld.exe --defaults-file=tools/mariadb-10.11.19-winx64/my.ini
```

> 访问必须用 `http://localhost:8080/index.php`（与 `site_url` 一致），用 `127.0.0.1` 会丢会话。

| # | 现象 | 根因 | 解决 |
|---|---|---|---|
| 1 | 静默安装一开始就 `Failed opening required modules/UpgradeWizard/uw_utils.php` | SuiteCRM 7.15.x 发布包删除了该文件，但 `install/install_utils.php` 仍无条件 require | 补齐上游 7.14.9 的同名函数实现，仅补缺失、不改既有文件 |
| 2 | 新模块建表 SQL 只渲染不执行 | `RepairAndClear::repairDatabase()` 默认只输出 SQL 表单 | CLI 下显式 `$repair->execute = true;` |
| 3 | 新模块不建表 | `entryPoint.php` 启动时已加载旧的 `modules.ext.php`，内存 `$beanList` 不含新模块 | repair 中 rebuild 后重新 `include 'custom/application/Ext/Include/modules.ext.php'` |
| 4 | 建表报 `Key column 'account_id' doesn't exist` | 外键名被生成为 `account_name_id` | `preg_replace('/_name$/','_id',$name)` 推导外键名 |
| 5 | 页面 500：`Cannot access offset of type <Bean> in isset or empty` | currency 字段的 `function` 误写为 `getCurrencyId`（签名 `($module,$id)`） | 改为 `getCurrencyDropDown`（`returns=html`） |
| 6 | 界面显示 `LBL_XXX` 原始键名 | 模块语言包被缓存到 `cache/modules/<Mod>/language/<lang>.lang.php` | repair 中显式删除该缓存目录下的 lang 文件 |
| 7 | 新模块不出现在顶部导航 | 导航读 `config.MySettings.tab`，不是 `include/tabConfig.php` | 写 `register-modules.php` 序列化写入该设置 |
| 8 | 详情页只有标题、内容区空白 | `tabDefs` 所有面板 `newTab=false` → `.tab-content` 为空、面板全部 `display:none` | 每个面板 `newTab => true` |
| 9 | 看板页面渲染成空列表 | `action=index` 被 `action_remap` 重映射为 `listview` | 视图命名为 `views/view.list.php`，类名 `...ViewList` |
| 10 | 成交周期算出负数（-10 天） | 手工 SQL 回填 `date_entered` 时用了 `$db->quote()`，该版本只转义**不加引号** → SQL 静默失败 | 改用 `$db->quoted()`（返回带引号字面量），并加执行结果校验与自检输出 |
| 11 | 演示首页「我的商机/我的客户」全空 | Dashlet 按 `assigned_user_id = 当前用户` 过滤，数据全挂在另一个账号 | 让内置 admin 兼任演示主账号（显示名张浩然），业务数据归属与登录账号一致 |
| 12 | `.gitignore` 把二次开发源码排除在版本库外 | 误把 `custom/Extension/modules/*/Ext/` 当成编译产物 | 该目录是**源码**，从忽略列表移除；产物是 `custom/application/` 与 `custom/modules/*/Ext/` |
