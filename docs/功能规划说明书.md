# AI Enterprise CRM —— 功能规划说明书

> 版本：v1.0 ｜ 阶段：第一阶段（可展示版本）
> 项目：面向 AI 企业解决方案销售团队的客户管理与销售流程优化平台
> 基础平台：SuiteCRM 7.15.2（开源，AGPL-3.0）

---

## 一、项目定位

### 1.1 一句话定位

以 SuiteCRM 为底座，通过**配置优化、字段扩展、流程重构、报表增强**，把一套通用开源 CRM 改造为 **"智联AI科技有限公司"** 销售团队专用的、覆盖 **线索 → 商机 → 需求调研 → 成交 → 项目交接** 全链路的 B 端业务系统。

### 1.2 为什么基于 SuiteCRM 而不是自研

| 维度 | 自研 CRM | 基于 SuiteCRM 改造 |
|---|---|---|
| 可信度 | 面试官易质疑"练手项目" | 真实企业软件，B 端业务能力配套完整 |
| 成本 | 需从零实现权限、审批、报表 | 复用成熟的企业级能力（RBAC、工作流、报表、API） |
| 重点 | 被技术实现拖累 | 聚焦 **产品设计 + 业务流程 + 客户需求分析** |
| 风险 | 交付不可控 | 成熟架构，稳定可运行 |

本项目**不重写 CRM**，所有改造遵循 **"扩展优先、覆盖次之、不破坏核心"** 的原则。

### 1.3 目标岗位能力映射

| 目标岗位 | 本项目对应的展示点 |
|---|---|
| 产品助理 | 模块规划、字段设计、原型交互、PRD/规划文档 |
| 产品运营 | 数据看板、漏斗分析、数据字典与运营指标口径 |
| 售前顾问 | 客户需求调研模块、方案设计流程、竞争产品/风险登记 |
| 实施顾问 | 销售到交付交接流程、验收标准、实施周期管理 |
| 客户成功 | 客户生命周期管理、客户等级/价值分层、跟进记录闭环 |
| 项目管理 | 三阶段路线图、里程碑与交付物管理、变更记录 |

## 二、模拟业务场景

### 2.1 模拟公司

- **公司名称**：智联AI科技有限公司（简称"智联AI"）
- **业务模式**：面向企业客户（B 端）销售 AI 解决方案，销售周期长、决策链复杂、需要售前与交付协同

### 2.2 产品线

| 产品代号 | 产品名称 | 价值主张 | 典型客单价 |
|---|---|---|---|
| P1 | AI 知识库系统 | 沉淀企业知识、降低客服与培训成本 | 20–80 万 |
| P2 | 企业智能客服 | 7×24 自动应答、降低人力成本 | 30–120 万 |
| P3 | AI 办公助手 | 文档处理、会议纪要、流程提效 | 10–50 万 |
| P4 | 数据分析平台 | 多源数据接入、经营分析看板 | 50–200 万 |

### 2.3 角色与职责（RBAC 设计依据）

| 角色 | 关键动作 | 在系统中的落点 |
|---|---|---|
| **销售人员** | 找线索、录客户、推商机、记录跟进 | Leads / Accounts / Opportunities / 跟进记录 |
| **售前顾问** | 需求分析、方案设计、技术交流 | **Customer Requirements**（需求调研模块） |
| **项目交付人员** | 项目实施、上线、验收 | **Project Handover**（项目交接模块） |
| 销售管理者 | 看漏斗、看业绩、看预测 | Dashboard / 销售漏斗分析 |

### 2.4 端到端业务流程（LTC：Lead to Cash）

```
[线索 Leads] ──转化──> [客户 Accounts] ──创建──> [商机 Opportunities]
                                                        │
                          ┌─────────────────────────────┤
                          │                             │
                 需求调研(Customer Requirements)    产品演示 / 商务谈判
                          │                             │
                          └──────────┬──────────────────┘
                                     │
                            ┌────────┴────────┐
                         [成交]            [输单]
                            │                 │
                  项目交接(Project Handover)  输单原因归档
                            │
                    [实施 → 上线 → 验收]
```

**关键协同点**：成交后由系统自动生成"项目交接单"，把销售/售前沉淀的客户需求、承诺功能、风险事项一并交接给交付团队 —— 这是本项目区别于普通 CRM 的核心业务亮点。

## 三、系统架构

### 3.1 技术栈（本地部署版）

| 层 | 组件 | 版本 | 说明 |
|---|---|---|---|
| 应用 | SuiteCRM | 7.15.2 | 开源企业级 CRM |
| 运行时 | PHP (NTS, Win64) | 8.3.x | 兼容矩阵支持 8.1–8.4 |
| 数据库 | MariaDB | 10.11 LTS | SuiteCRM 官方推荐 |
| Web 服务 | PHP 内置服务器 / Apache | — | 开发期用 `php -S`，生产建议 Apache |
| 版本管理 | Git | 2.55 | 改造全过程留痕 |

### 3.2 改造分层策略

```
┌─────────────────────────────────────────────┐
│  ① 配置层（Studio / 管理后台）                 │  ← 零代码：下拉项、布局、标签、权限
├─────────────────────────────────────────────┤
│  ② 扩展层（custom/ 目录 + vardefs 覆盖）       │  ← 低代码：字段追加、模块扩展、logic hook
├─────────────────────────────────────────────┤
│  ③ 增强层（自定义 Dashlet / 报表 / 视图）      │  ← 报表：Dashboard、销售漏斗、指标卡
├─────────────────────────────────────────────┤
│  ④ 核心层（SuiteCRM 原生代码）                 │  ← 不动！保持可升级性
└─────────────────────────────────────────────┘
```

**铁律**：所有改动沉淀在 `custom/` 与 `modules/*/metadata|vardefs` 覆盖文件中，**不修改 SuiteCRM 核心源码**，保证后续可平滑升级。

### 3.3 模块复用与新增对照表

| 需求 | SuiteCRM 原生模块 | 处理方式 |
|---|---|---|
| 客户生命周期 | Accounts（客户）/ Leads（线索）/ Contacts（联系人） | **扩展字段 + 布局 + 中文标签** |
| 商机管理 | Opportunities | **扩展字段 + 重构销售阶段** |
| 跟进记录 | Calls / Meetings / Tasks / Notes | 直接复用（中文标签） |
| 需求调研 | —— | **新增模块** `CReq_CustomerRequirements` |
| 项目交接 | ——（原生 Projects 偏任务管理） | **新增模块** `PH_ProjectHandover` |
| 销售分析 | Dashlets + AOR_Reports | **自定义 Dashlet + 报表** |
| 工作流 | Workflow（原生） | 配置：阶段联动、自动建交接单 |

## 四、功能模块详细规划

### 4.1 功能一：客户生命周期管理（扩展 Accounts）

**目标**：让"客户"这个对象承载完整的 B 端客户画像，从线索到成交全程可追踪。

#### 新增字段清单

| 分组 | 字段标签 | 字段名（技术） | 类型 | 取值 / 说明 |
|---|---|---|---|---|
| 基础信息 | 所属行业 | `industry`（原生扩展） | 下拉 | 制造业/金融/医疗健康/互联网/教育/能源/政府/零售/物流 |
| 基础信息 | 公司规模 | `company_size_c` | 下拉 | 1-50人/51-200人/201-500人/501-1000人/1000人以上 |
| 基础信息 | 企业类型 | `enterprise_type_c` | 下拉 | 国有企业/民营企业/外资企业/合资企业/上市公司/政府机构 |
| 客户价值 | 客户等级 | `customer_level_c` | 下拉 | A-战略/B-重点/C-普通/D-潜在 |
| 客户价值 | 客户来源 | `customer_source_c` | 下拉 | 官网咨询/行业展会/客户转介绍/陌生拜访/市场活动/渠道合作/搜索引擎 |
| 客户价值 | 潜在价值 | `potential_value_c` | 货币 | 预计可挖掘的合同总额 |
| 业务信息 | 当前痛点 | `current_pain_points_c` | 文本域 | 例："客服人力成本高、知识分散难检索" |
| 业务信息 | 使用系统 | `current_system_c` | 文本 | 当前在用的竞品/自研系统 |
| 业务信息 | 预算范围 | `budget_range_c` | 下拉 | 10万以下/10-30万/30-50万/50-100万/100万以上 |
| 业务信息 | 决策周期 | `decision_cycle_c` | 下拉 | 1个月内/1-3个月/3-6个月/6个月以上 |
| 负责人 | 销售负责人 | `sales_owner_c` | 关联用户 | 销售归属 |
| 负责人 | 售前负责人 | `presales_owner_c` | 关联用户 | 售前支撑人 |

> **设计说明**：`_c` 后缀为 SuiteCRM Studio/Module Builder 生成的自定义字段标准命名，可避免与原生字段冲突。

### 4.2 功能二：AI 解决方案销售商机管理（重构 Opportunities）

**目标**：把通用商机对象改造为"按产品线 + 按销售阶段"的 AI 解决方案销售管道。

#### 新增 / 重构字段

| 字段标签 | 字段名 | 类型 | 说明 |
|---|---|---|---|
| 商机名称 | `name`（原生） | 文本 | 建议命名：`客户简称-AI客服-2026Q4` |
| 产品类型 | `product_type_c` | 单选下拉 | AI知识库 / AI客服 / AI办公助手 / 数据分析平台（单选便于按产品聚合销售金额） |
| 销售阶段 | `sales_stage`（重构） | 下拉 | 见下方阶段定义 |
| 预计金额 | `amount`（原生） | 货币 | 商机预估合同额 |
| 成交概率 | `probability`（原生） | 整数 | 与阶段联动（见下） |
| 预计成交时间 | `date_closed`（原生） | 日期 | 预测成交日 |
| 下一步计划 | `next_step`（原生复用） | 文本 | SuiteCRM 原生已有该字段，直接复用并中文化标签 |
| 输单原因 | `lost_reason_c` | 下拉 | 仅"输单"阶段显示（dependency 联动） |

#### 销售阶段重构方案（关键设计）

| 展示标签 | 阶段 Key（保持英文，勿改） | 默认成交概率 |
|---|---|---|
| 初步接触 | `Prospecting` | 10% |
| 需求调研 | `Needs Analysis` | 25% |
| 方案设计 | `Value Proposition` | 40% |
| 产品演示 | `Perception Analysis` | 55% |
| 商务谈判 | `Negotiation/Review` | 75% |
| **成交** | `Closed Won` | 100% |
| **输单** | `Closed Lost` | 0% |

> ⚠️ **重要设计约束（体现企业系统理解）**：
> SuiteCRM 内部通过 `Closed Won` / `Closed Lost` 两个**英文 Key** 判断商机是否关闭，并驱动漏斗统计、预测金额与概率计算。若把 Key 直接改成中文，会导致**漏斗与报表失效**。
> **正确做法**：保留英文 Key 不动，仅通过语言包把 **显示标签** 中文化。这样既满足界面中文化，又不破坏统计逻辑。
> 同时，用户任务书中的"产品演示"阶段在原标准阶段表中无直接对应，本方案映射到 `Perception Analysis` 并保留其原始权重，保证概率模型连续。

#### 输单原因（`lost_reason_c`）下拉项

价格竞争力不足 / 产品功能不满足 / 实施与交付周期 / 选择竞品 / 预算取消或延期 / 决策流程变更 / 客户关系因素 / 其他

#### 自动化规则

| # | 规则 | 落地方式 | 状态 |
|---|---|---|---|
| 1 | 商机阶段变更为「成交」→ 自动生成项目交接单 + 派发交接准备待办 | Opportunities `after_save` 逻辑钩子 | 已实现（`scripts/verify/verify-automation.php` 验收） |
| 2 | 商机阶段变更 → 成交概率自动带入阶段默认值 | 销售阶段与概率下拉联动（`sales_probability_dom`） | 已实现（配置层） |
| 3 | 商机阶段变更为「输单」→ 强制填写输单原因 | 输单原因字段必填校验 | 规划中（Stage 2） |
| 4 | 商机 30 天未更新 → 生成提醒任务给销售负责人 | SuiteCRM Workflow（AOW）定时规则 | 规划中（Stage 2） |

> 设计取舍：规则 1 用**逻辑钩子**而非 AOW 工作流，是因为交付起点必须在销售点击保存的**同一秒**发生，
> 不能依赖调度器的轮询周期；规则 4 属于"慢动作提醒"，更适合交给 AOW 定时执行。

### 4.4 功能四：销售漏斗分析 Dashboard

**目标**：把销售管理者的决策依据做成一个"打开即用"的企业级看板。

#### 首页 Dashboard 布局规划

```
┌───────────────────────────────────────────────────────────────┐
│  [指标卡] 客户数  [指标卡] 商机数  [指标卡] 预计金额  [指标卡] 成交金额  [指标卡] 平均成交周期 │
├───────────────────────────────┬───────────────────────────────┤
│  销售漏斗图（按阶段）           │  产品销售金额（柱状）           │
├───────────────────────────────┼───────────────────────────────┤
│  输单原因统计（饼图）           │  客户行业分布（饼/环图）         │
├───────────────────────────────┴───────────────────────────────┤
│  我的商机 Dashlet  ｜  最近跟进记录  ｜  待办任务                │
└───────────────────────────────────────────────────────────────┘
```

#### 核心指标定义（口径明确，面试可讲）

| 指标 | 计算口径 |
|---|---|
| 客户数量 | `Accounts` 状态为 Active 的记录数 |
| 商机数量 | `Opportunities` 非关闭（未成交未输单）记录数 |
| 预计销售金额 | 所有进行中商机 `amount` 合计 |
| 成交金额 | 阶段 = `Closed Won` 的商机 `amount` 合计 |
| 平均成交周期 | `AVG(成交商机.date_closed − date_entered)`，单位：天 |
| 赢单率 | 成交商机数 ÷（成交 + 输单）商机数 |

#### 分析图表清单

1. **不同阶段商机数量** —— 漏斗图（Funnel）
2. **不同产品销售金额** —— 按 `product_type_c` 聚合的柱状图
3. **输单原因统计** —— 按 `lost_reason_c` 聚合的饼图
4. **客户行业分布** —— 按 `industry` 聚合的环形图

**实现路径（落地结果）**：
- 采用**自定义模块 + 自定义视图**的方式实现：新增纯展示型模块 `AID_SalesAnalytics`（销售分析），
  其 `views/view.list.php` 渲染整块看板（KPI + 5 张 ECharts 图表），
  与首页原生 Dashlet 并存 —— 首页承载"我的待办/我的商机"，看板承载"经营分析"。
- 图表库使用 **本地 ECharts 5.5.1**（`custom/include/ai_assets/echarts.min.js`），无外网 CDN 依赖。
- 所有数据实时取自业务库（`opportunities` / `accounts`），不落地中间表，避免数据不一致。

#### 5 个核心指标卡

| 指标 | 计算口径 | 示例值 |
|---|---|---|
| 客户总数 | `COUNT(accounts WHERE deleted=0)` | 20 家 |
| 商机总数 | `COUNT(opportunities WHERE deleted=0)` | 30 个 |
| 在途预计金额 | `SUM(amount)` 且阶段 ∉ (成交, 输单) | 1,315.2 万元 |
| 已成交金额 | `SUM(amount)` 且阶段 = 成交 | 223.4 万元 |
| 商机成交率 | 成交数 ÷（成交 + 输单） | 75% |
| 平均成交周期 | `AVG(DATEDIFF(date_closed, DATE(date_entered)))` | 86 天 |

#### 分析图表清单（落地结果）

1. **销售漏斗** —— 漏斗图，**累计口径**（进入该阶段及后续阶段的商机数），成交转化率 21.4%
2. **各阶段商机数量** —— 柱状（商机数）+ 折线（金额，双 Y 轴）
3. **产品销售金额** —— 横向条形图，按 `product_type_c` 聚合
4. **客户行业分布** —— 环形图，按 `industry` 聚合
5. **输单原因分析** —— 横向条形图，按 `lost_reason_c` 聚合，Tooltip 带出涉及金额

### 4.5 功能五：销售到交付流程（新增 `Hand_ProjectHandovers`）

**目标**：成交不是终点，把"销售承诺"无损交接给交付团队，体现销售—售前—交付三角协同。

#### 字段清单（★ 为落地实现后的最终字段名）

## 五、数据模型与关系（ER 概览）

```
Leads ──转化──> Accounts ──1:N──> Opportunities ──1:N──> Hand_ProjectHandovers
                    │                    │
                    │                    │
                    └──1:N──> CReq_CustomerRequirements ──N:1──┘
                    │
                    └──1:N──> Contacts / Calls / Meetings / Tasks（跟进记录）

AID_SalesAnalytics（销售分析看板）：无业务表，实时聚合 Accounts + Opportunities
```

- **Accounts → Opportunities**：一对多（一个客户多个商机）
- **Accounts → CReq_CustomerRequirements**：一对多
- **Opportunities → CReq_CustomerRequirements**：一对多
- **Accounts / Opportunities → Hand_ProjectHandovers**：一对多（成交商机自动生成）

### 物理表清单（自定义部分）

| 表名 | 对应模块 | 说明 |
|---|---|---|
| `creq_customerrequirements` | CReq_CustomerRequirements | 需求调研记录（27 列） |
| `hand_projecthandovers` | Hand_ProjectHandovers | 项目交接单（26 列） |
| `aid_salesanalytics` | AID_SalesAnalytics | 看板占位表（9 列，仅承载模块元数据） |

## 九、风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 销售阶段 Key 中文化导致报表失效 | 漏斗/预测错误 | Key 保持英文，仅标签中文化 |
| 自定义字段与原生字段冲突 | 页面异常 | 统一 `_c` 后缀命名 |
| 修改核心代码导致无法升级 | 维护成本高 | 改动只进 `custom/` 与 metadata 覆盖 |
| 数据关联不一致 | 看板数据错乱 | 导入前先建关系表，按 ID 关联 |
| 部署环境差异 | 换机跑不起来 | 提供 `scripts/` 一键部署脚本 + README |
