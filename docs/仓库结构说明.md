# 仓库结构说明

本文档说明本仓库的组织规范、目录职责与入库范围，
便于他人快速理解"仓库里有什么、为什么这样放、如何复现运行"。

---

## 一、整理目标与结果

本仓库定位为 **SuiteCRM 二次开发作品仓库**，整理遵循三条原则：

| 原则 | 说明 |
|---|---|
| **只放本项目产出** | SuiteCRM 上游源码不入库，由部署流程获取 |
| **源码与产物分离** | 编译产物、运行时文件、本地环境一律排除 |
| **层级按用途划分** | 文档 / 部署 / 脚本 / 截图 / 应用代码各归其位 |

### 整理前后对比

| 维度 | 整理前 | 整理后 |
|---|---|---|
| 入库文件数 | 9,490 | **323** |
| 其中本项目产出 | 约 160 | **323（100%）** |
| 仓库体积 | 197 MB | **约 4 MB** |
| Git 历史 | 含上游 9330 文件 / 132 万行 | 仅本项目自有提交，按功能分层重建 |
| GitHub 语言占比 | PHP 被第三方代码主导 | 真实反映本项目编写量 |

### 主要变化点

- **移除上游源码**：SuiteCRM 7.15.2 的 9,330 个文件不再入库
- **清除编译产物**：`custom/modules/*/Ext/`、`custom/application/`、`logic_hooks.php` 等 73 个文件改为排除，由修复重建流程重新生成
- **分离第三方资源**：136 个中文本地化文件从 `crm/` 迁出至 `deploy/i18n/`
- **补丁化核心改动**：唯一的核心目录补丁移入 `deploy/patches/`
- **脚本按用途分组**：12 个脚本从单层目录重组为 5 个语义分组
- **补齐工程规范**：新增 `LICENSE`、`.gitattributes`、`.editorconfig`、`CHANGELOG.md`、`CONTRIBUTING.md`、`.github/`
- **清理临时文件**：移除 19 个开发期调试产物与 2 个一次性诊断脚本
- **凭据脱敏**：`config_si.php.example` 与 `.env.example` 中的真实密码替换为占位符

## 四、入库范围与排除规则

`.gitignore` 采用**精确白名单**策略：`crm/` 下默认全部排除，
仅放行本项目自己编写的内容。

### 4.1 放行规则

```gitignore
/crm/*
!/crm/custom/
!/crm/modules/
!/crm/config_override.php
!/crm/config_si.php.example
!/crm/.htaccess

/crm/modules/*
!/crm/modules/AID_SalesAnalytics/
!/crm/modules/CReq_CustomerRequirements/
!/crm/modules/Hand_ProjectHandovers/
```

> 新增自研模块时，需同步在 `.gitignore` 中补充放行规则。

### 4.2 关键区分：源码 vs 编译产物

这是本项目最容易踩错的一点：

| 路径 | 性质 | 是否入库 |
|---|---|---|
| `crm/custom/Extension/**` | 扩展**源码**（Vardefs / Layoutdefs / Language / LogicHooks） | ✅ 必须入库 |
| `crm/custom/modules/*/metadata/*.php` | 视图布局覆盖（手工编写） | ✅ 入库 |
| `crm/custom/modules/*/Ext/**` | 由 Quick Repair 合并生成 | ❌ 排除 |
| `crm/custom/application/**` | 由 Quick Repair 合并生成 | ❌ 排除 |
| `crm/custom/modules/*/logic_hooks.php` | 文件头自述"will be automatically rebuilt" | ❌ 排除 |

### 4.3 排除清单

| 类别 | 路径 | 原因 |
|---|---|---|
| 上游源码 | `crm/` 除白名单外全部 | 由部署流程获取 |
| 编译产物 | `crm/custom/application/`、`crm/custom/modules/*/Ext/`、`**/logic_hooks.php` | 可重新生成 |
| 第三方依赖 | `crm/vendor/`、`node_modules/` | 由包管理器安装 |
| 运行时 | `crm/cache/`、`crm/upload/`、`crm/tmp/`、`*.log` | 动态生成 |
| 本地环境 | `tools/`、`data/` | 体积大、含环境相关信息 |
| **凭据** | `crm/config.php`、`crm/config_si.php`、`data/.pw` | 含密码 |
| 临时产物 | `data/_*.html`、`data/dbg.html`、`*.bak`、`*.tmp` | 开发期残留 |

## 六、如何验证整理结果

### 6.1 确认只包含本项目产出

```bash
# 应输出为空：crm/ 下任何改动都落在 custom/、3 个自研模块或 config_override.php 内
git ls-files crm/ \
  | grep -vE "^crm/(custom/|modules/(AID_SalesAnalytics|CReq_CustomerRequirements|Hand_ProjectHandovers)/|config_override\.php|config_si\.php\.example|\.htaccess$)"
```

### 6.2 确认编译产物未被误入库

```bash
# 以下三条均应输出 0
git ls-files | grep -c "/Ext/"                     # custom/modules/*/Ext/
git ls-files | grep -c "logic_hooks\.php"          # 钩子合并产物
git ls-files | grep -c "^crm/custom/application/"  # 扩展合并产物
```

### 6.3 确认无凭据泄漏

```bash
# 应无输出（data/.pw 已被忽略）
grep -rlF "$(cat data/.pw)" . \
  --exclude-dir=.git --exclude-dir=tools --exclude-dir=data
```

### 6.4 确认本地仍可正常运行

```bash
tools/php/php.exe scripts/verify/verify-customizations.php
tools/php/php.exe scripts/verify/verify-automation.php
```

## 七、从零复现

本仓库不含上游源码与本地环境，完整复现需三步：

```bash
# 第一步：获取 SuiteCRM 7.15.2 并解压到 crm/
#   https://github.com/SuiteCRM/SuiteCRM/releases/tag/v7.15.2
#   解压时选择「不覆盖已存在文件」，保留仓库中的定制内容

# 第二步：释放中文语言包与兼容补丁
bash deploy/native/apply-overlay.sh

# 第三步：按 deploy/native/README.md 完成安装、修复重建与演示数据生成
```

Docker 方式见 [`../deploy/docker/`](../deploy/docker/)，
本地便携栈方式见 [`../deploy/native/README.md`](../deploy/native/README.md)。
