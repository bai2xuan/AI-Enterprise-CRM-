## 四、关键技术实现（代码级）

### 4.1 客户字段扩展（Vardefs）

```php
// crm/custom/Extension/modules/Accounts/Ext/Vardefs/ai_accounts_fields.php
$dictionary['Account']['fields']['company_size_c'] = array(
    'name'    => 'company_size_c',
    'vname'   => 'LBL_COMPANY_SIZE',
    'type'    => 'enum',
    'options' => 'ai_company_size_list',
    'len'     => 100,
    'audited' => true,
);
```

要点：
- `vname` 指向语言键，**必须**在对应语言文件里定义，否则界面显示 `LBL_COMPANY_SIZE`；
- 枚举型必须通过 `options` 指向 `app_list_strings` 中的字典键；
- 自定义字段统一 `_c` 后缀；
- `audited = true` 让字段变更进入审计表。

### 4.2 relate 字段（关联用户）

```php
// company_size_c 之后
'vname'     => 'LBL_SALES_OWNER',
'type'      => 'relate',
'module'    => 'Users',
'id_name'   => 'sales_owner_c_user_id',   // 外键列
'ext2'      => 'Users',
'rname'     => 'name',
```
SuiteCRM 的 relate 字段是「三件套」：显示字段（`sales_owner_c`）、外键（`sales_owner_c_user_id`）、link。
生成器自动推导外键名，避免手工写错导致建表失败。

### 4.3 currency 字段（易踩坑）

```php
'potential_value_c' => array(
    'name' => 'potential_value_c', 'type' => 'currency', 'vname' => 'LBL_POTENTIAL_VALUE',
),
// 必须配套：
'currency_id' => array(
    'name' => 'currency_id', 'type' => 'id', 'group' => 'currency_id',
    'function' => array('name' => 'getCurrencyDropDown', 'returns' => 'html'),
),
```
若把 `function.name` 误写成 `getCurrencyId`（签名是 `($module, $id)`），
搜索表单会把 Bean 对象当模块名传入，直接触发致命错误。

### 4.4 布局覆盖（viewdefs）

`custom/modules/<Mod>/metadata/detailviewdefs.php` 是**完整替换**，因此策略是
「复制核心文件 → 按精确片段插入新 panel」，而不是 `include + var_export` 重新生成
（文件内含 `EmailAddress::getSendConfirmOptInEmailActionLinkDefs()` 这类运行时调用）。

**页签约束**：`templateMeta.tabDefs` 中每个面板必须 `newTab => true`。

### 4.5 业务自动化（逻辑钩子）

```php
// crm/custom/Extension/modules/Opportunities/Ext/LogicHooks/ai_handover_hook.php
$hook_array['after_save'][] = array(
    60, '商机成交后自动生成项目交接单',
    'custom/modules/Opportunities/ai_handover_hook.php',
    'AI_OpportunityHandoverHook', 'afterSave',
);
```

实现要点：

| 要点 | 做法 |
|---|---|
| 触发条件 | `sales_stage === 'Closed Won'` 且已有 `id` |
| 幂等 | 先按 `opportunity_id` 查已有交接单，存在即返回 |
| 防重入 | 全局标记 `ai_handover_hook_running`，保护嵌套保存 |
| 异常隔离 | `try/catch` + `$GLOBALS['log']->error()`，避免钩子异常影响保存主流程 |
| 数据继承 | 客户 / 商机 / 产品 / 合同金额 / 货币 / 负责人由商机带出 |
| 派生动作 | 同时创建「项目交接准备」待办，形成动作闭环 |

### 4.6 本地化三件套

| 层 | 文件 | 作用 |
|---|---|---|
| 系统默认 | `config_override.php` | 新用户/新会话的默认语言、货币、日期格式 |
| 界面文案 | `custom/Extension/**/Language/zh_CN.*.php` | 覆盖官方语言包的英文残留（Accounts 42 处、Opportunities 15 处、Home 29 处等） |
| 用户偏好 | `scripts/setup/apply-locale-preferences.php` | 回写 `user_preferences`，修正静默安装遗留的 `m/d/Y` |

> 为什么官方中文包不够用：SuiteCRM 官方 zh_CN 语言包存在大量未翻译条目（app 级 201 处），
> 本项目用「扩展覆盖」而不是「改核心语言文件」，保证升级后仍生效。

## 五、核心代码改动声明

**业务逻辑改动：0 行。**

唯一一处落在核心目录的改动，是**部署期缺陷兼容补丁**，且已归入基线提交 `948b553`：

| 文件 | 性质 | 说明 |
|---|---|---|
| `crm/modules/UpgradeWizard/uw_utils.php` | 上游缺失文件补齐 | SuiteCRM 7.15.x 发布包删除了该文件，但 `install/install_utils.php` 第 938 行仍无条件 `require` 它，导致 `config_si.php` 静默安装必然中断。本项目从上游 7.14.9 补齐 `merge_config_si_settings()` 同名实现，**仅补缺失函数，不修改任何既有文件**。 |

**验证方式**（可复现）：

```bash
BASE=$(git log --oneline | tail -1 | cut -d' ' -f1)          # 基线提交
{ git diff --name-only $BASE HEAD; git status --short | awk '{print $2}'; } \
  | sort -u \
  | grep -vE "^crm/custom/|^crm/modules/(CReq_CustomerRequirements|Hand_ProjectHandovers|AID_SalesAnalytics)/|^scripts/|^docs/|^screenshots/|^deploy/|^README.md|^\.gitignore|^data/|^crm/config_override.php"
# 输出为空 → 业务代码零改动
```

实测：应用层定制文件共 127 个，全部落在 `crm/custom/`、3 个自研模块目录与
`crm/config_override.php` 之内；连同脚本（13）、部署资源（149）、文档（8）、
界面截图（14）与仓库根配置，**入库文件共 324 个，全部为本项目产出**。

> 仓库不收录 SuiteCRM 上游源码，因此不存在「上游文件被改动」的可能性。
> 组织规则与校验命令见 [`仓库结构说明.md`](仓库结构说明.md)。

## 六、升级安全性分析

当 SuiteCRM 从 7.15.2 升级到更高版本时：

| 内容 | 位置 | 升级后是否保留 |
|---|---|---|
| 客户/商机自定义字段 | `custom/Extension/modules/*/Ext/Vardefs/` | 保留（官方扩展目录） |
| 页面布局覆盖 | `custom/modules/*/metadata/` | 保留（官方覆盖目录） |
| 中文化语言包 | `custom/Extension/**/Language/` | 保留 |
| 逻辑钩子 | `custom/Extension/**/LogicHooks/` + `custom/modules/Opportunities/` | 保留 |
| 三个自定义模块 | `modules/CReq_*` / `Hand_*` / `AID_*` | 保留（非上游模块目录，不会被覆盖） |
| 项目配置 | `crm/config_override.php` | 保留（升级不写此文件） |
| 图表资源 | `custom/include/ai_assets/` | 保留 |
| 扩展合并产物 | `custom/application/`、`custom/modules/*/Ext/` | 会被重建（无需保留） |
| 数据库业务数据 | `creq_*` / `hand_*` 表 | 保留（不在升级删除范围） |

**升级操作清单**：跑一次 `php scripts/setup/repair.php`（重建扩展 + 清理缓存），
再跑 `php scripts/verify/verify-customizations.php` 断言 96 项定制全部生效即可。
